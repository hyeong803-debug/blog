# /write — 초안 작성 → 승인 → 임시저장

입력: $ARGUMENTS
(사진: `input/photos/`, 영상: `input/videos/`)

CLAUDE.md 의 절대 규칙·글쓰기 공식·자가 검증 원칙을 그대로 따른다. 단계마다 "됐는지 확인"으로 끝낸다.

## 1단계 — 자료 읽기
1. `CLAUDE.md` 와 `data/` 전부 읽기: profile, blogger-profile, authority-lines, keywords, insurance-compliance, photo-guide, sponsored-disclosure, style-profile, trends, post-history.
2. `input/photos/` 의 사진을 **전부 Read 로 직접 본다** (`_mosaic/` 제외). 사진마다 무엇이 보이는지 1줄 메모. `input/videos/` 확인.
3. post-history.md 에서 이미 쓴 사진 파일명 → 재사용 금지.

## 2단계 — 확인 질문 (하나라도 불명확하면 글 쓰기 전에 한 번에 묻는다)
- **협찬·체험단 여부** (메모에 없으면 반드시 질문). 협찬이면 대가 유형 + 업체 지정 문구 유무.
- 글 유형: 보험 정보성 / 상담·일상 / 체험단 리뷰 — 그리고 보험이면 `adType` (정보성 / 상품광고 — 상품광고면 심의필 번호).
- 메인 키워드 확정 (keywords.md 에서 2~3개 후보 제시 → 사용자 선택, 직전 글과 중복 금지).
- 글에 필요한데 profile.md 에 없는 사실 (TODO 항목, 가격·수치·날짜·장소명 등). **추측해서 채우지 않는다.** 답을 받으면 profile.md 에 기록.
- AI 생성 이미지가 섞여 있는지 (구분이 애매하면 질문).

## 3단계 — 개인정보 모자이크
- 사진에서 타인 얼굴·번호판·전화번호·이름·주민/증권/계좌번호·병원명·진단명·화자 실물 얼굴을 찾는다.
- 있으면: `drafts/<초안명>.mosaic.json` 작성 (EXIF 회전 보정 후 화면 기준 0~1 좌표) → `node scripts/mosaic.js drafts/<초안명>.mosaic.json` → **처리본을 Read 로 열어 확인** → 덜 가려졌으면 좌표 키워 재실행 → 초안엔 처리본 경로.

## 4단계 — 설계 (초안 쓰기 전에 정한다)
- 페르소나 1명 (지역·나이·직책·상황·감정)
- 메인 1 + 서브 2~3 키워드, 제목(25~32자, 메인 키워드 앞쪽)
- 후킹 패턴 (직전 3개와 다르게), 도입 패턴, 권위 문구 (솔직함형 우선, 숫자형은 profile 확정 시만)
- 사진 스토리 순서 (파일 순서 아님), 캡션 넣을 사진 = 절반 정도
- 업종별 필수 정보 체크리스트(CLAUDE.md §2) 항목별로 채울 내용 / 모르는 항목

## 5단계 — 초안 작성
- `drafts/YYYYMMDD-<slug>.json` (CLAUDE.md §4 포맷). 말투는 blogger-profile.md.
- 첫 문단 Yes-set + 결론 예고, 둘째 문단 권위 1줄, 300~400자마다 리듬 장치, 인용구 2~4개, 한 문장 한 줄, 한 블록 3~5줄.
- 협찬이면 blocks[0] = 협찬 표기 text 블록. 보험 글은 insurance-compliance.md 기본 문구.
- `tags` 5~10개, 지역 글이면 `place` (profile.md 에 플레이스명 있을 때만), 영상 있으면 `video`.

## 6단계 — 자동 검수 + 자가 검수
1. `node scripts/lint_draft.js drafts/<초안>.json` → 오류 0 될 때까지 수정. 경고는 이유가 있으면 유지하고 보고.
2. 자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"

## 7단계 — 검수 보고 (사용자에게)
아래를 한 번에 보여주고 **승인을 기다린다** (승인 전 임시저장 금지):
- 페르소나 / 메인·서브 키워드 / 후킹·도입·권위 유형
- lint 결과 요약 (분량, 키워드 횟수, 사진 수, 인용구 수, 최장 텍스트 연속)
- 업종별 체크리스트 항목별 ✓/✗ (✗ 는 이유: 미확인 → 질문 or 제외)
- 모바일 훑어보기: 소제목 + 인용구만 순서대로
- 모자이크 처리 내역 (몇 장 · 몇 영역 · 사유)
- 협찬 표기 / 보험 광고 체크 결과
- 전문 미리보기 (블록 순서대로, 사진은 `[사진: 파일명 — 캡션]`)

## 8단계 — 승인 후 임시저장
1. `node scripts/naver_draft.js drafts/<초안>.json --dry-run` — **[추정] 셀렉터가 남아 있거나 직전 실행이 실패했으면 반드시 먼저**. 로그의 "자동 처리 결과" 확인.
2. dry-run 통과 → `node scripts/naver_draft.js drafts/<초안>.json`
3. **이중 검증:** `drafts/<초안>.verify/post-dump.txt` 를 Read 해서 초안과 전문 대조 + `post-screenshot.png` 를 Read 로 확인. 스크립트 판정과 별개로 직접 본다. 불일치 → 성공 보고 금지, 원인 수정.
4. 셀렉터 실패 → 추측 수정 금지. `node scripts/probe_selectors.js` (팝업이면 `--open`, 텍스트로 찾기 `--find`) 로 실측 → 수정 → dry-run. **3회 실패 시** `drafts/<초안>.manual.txt` 를 사용자에게 제공.
5. 문제를 해결했다면: CLAUDE.md §8 교훈 로그 기록 + 안정 스크립트를 `scripts/<이름>.working.js` 로 백업.

## 9단계 — 완료 보고
- "자동 처리 결과" 중 `! 수동 필요` 항목만 안내.
- 발행 체크리스트: 타겟 시간대 발행 / 발행 후 24시간 수정 금지 / 주 2~3회(하루 2건 이상 금지) / 협찬 표기 육안 확인 / (상품광고) 심의필 확인.
- 실패본이 "저장 글"에 쌓였으면 직접 정리 안내 (자동 삭제 금지).
- `data/post-history.md` 에 1줄 추가 (날짜·초안·메인 키워드·후킹·도입·권위·사진 파일명).
